# DOCMIND 새 서버 배포 AGENT 인수인계

이 문서는 이 저장소를 처음 받는 배포 AGENT가 사용자의 의도와 현재 상태를 이해하기 위한 맥락입니다. 실행 순서와 그림은 루트 [README.md](../README.md), 작업 규칙은 [AGENTS.md](../AGENTS.md)를 함께 읽습니다. 아래 설명은 배포 작업의 기준이며 대상 서버가 이미 준비되었다는 보장이 아닙니다.

## 사용자가 원하는 결과

현재 운영 중인 DOCMIND를 새 서버에서 같은 사용자 경험으로 시작하려는 작업입니다. 새 제품을 다시 설계하거나 범용 RAGFlow를 설치하는 작업이 아닙니다. 사용자는 비공개 저장소를 전달하면 배포팀/AGENT가 환경을 판단하고 설치를 마무리할 수 있기를 원합니다.

새 서버에는 GPU가 없습니다. 따라서 CPU로 인덱싱해야 하고 OCR은 사용하지 않습니다. 기존 운영 문서·벡터를 옮기는 대신 새 서버에서 지정한 원본 폴더를 읽어 빈 색인부터 구성합니다. 사용자가 수정하는 DOCMIND 설정은 **`deployment/source-folders.txt`에 쓰는 문서 폴더 주소 한 곳**이어야 합니다. 나머지 API·모델·공용 접속 설정을 다시 고르게 하지 않습니다.

처음에는 현재와 같은 Windows/WSL 환경으로 이해했지만 사용자가 이후 **환경이 다를 수 있으므로 현지 AGENT가 조사하고 판단하라**고 명확히 정정했습니다. Windows·WSL·Docker·복호화 프로그램이 이미 있다는 전제를 검증 없이 사용하지 마세요.

| 문서 경로만 사용자 입력 | 파일 서버 경로와 DOCMIND 서버 로컬 경로를 혼동하지 않습니다. 문서 루트는 명시적으로 지정하며 자동 탐색했다고 주장하지 않습니다. |

## 실제 구조와 데이터의 위치

Windows 수집기가 등록한 원본 루트를 감시하고, 승인된 `uEncryptor2.exe`로 필요한 문서를 임시 복호화합니다. Linux 컨테이너의 API에 전달한 뒤 Kordoc이 텍스트를 추출하고, CPU GTE가 벡터를 생성합니다. Elasticsearch에는 검색에 필요한 청크·벡터를 저장합니다. 원본 암호화 문서는 원래 폴더에 남고 임시 평문은 정리합니다.

브라우저 검색에서는 질문을 임베딩해 같은 문서 범위에서 키워드/벡터 검색을 수행하고 Jina로 후보를 재정렬합니다. 선택한 근거를 기존 외부 답변 API에 전달해 답변을 만듭니다. 질문할 때마다 전체 원본을 다시 복호화/인덱싱하는 구조가 아닙니다.

원문 미리보기는 별도 Windows 미리보기 worker가 임시 복호화하고 미리보기 processor가 처리합니다. 미리보기 결과는 tmpfs에 두며 정리 계약을 유지합니다. 영구 원문 사본을 MinIO에 저장하는 방식으로 대체하지 않습니다.

**MinIO에 대한 정확한 구분:** 현재 운영 컨테이너와 기본 저장소 클라이언트는 남아 있고, 별도 일반 파일/로컬 폴더 업로드 코드가 MinIO를 사용합니다. 반면 주력인 폴더 감시·cloud ephemeral 인덱싱은 원문/이미지 객체 저장을 우회하며 임시 미리보기도 객체 저장소를 호출하지 않습니다. 따라서 MinIO를 핵심 원문 보관소라고 설명하면 안 됩니다. 현재 패키지가 MinIO를 유지하는 이유는 일반 업로드 의존성입니다. 그 기능까지 조사·시험하지 않고 MinIO 전체 제거를 완료했다고 보고하지 마세요. 기존 MinIO 볼륨을 삭제하지 않습니다.

## 유지해야 할 제품 계약

- 임베딩은 `Alibaba-NLP/gte-multilingual-base`, 768차원, FP32, CLS pooling 및 L2 정규화를 유지합니다. 입력 한도 8192토큰을 넘으면 거부하며 조용히 잘라내지 않습니다.
- 모델/코드 revision은 `tools/local_embedding/download_model.py`와 `prepare_cpu_server.py`에 고정되어 있습니다. 임의의 최신 모델, 다른 차원, 다른 pooling으로 교체하지 않습니다.
- CPU 기본값은 2스레드, 임베딩 짧은 배치 1, 문서 처리 동시성 1입니다. 성능이 느리다고 바로 동시성을 늘리지 말고 현장 자원과 정리 동작을 먼저 확인합니다.
- 기존 청킹·검색 계약(C128, 청크별 prefix 2400자, Jina reranker v3.5)과 근거 문서 표시를 유지합니다. 모델 선택/설정 화면을 사용자에게 다시 노출하지 않습니다.
- Windows worker의 HMAC 인증, 실행 파일 해시/승인 서명 검사, 소스 경계, lease/fencing 및 cleanup receipt를 우회하지 않습니다. 수집과 미리보기의 평문/영수증 경로는 분리하며 복호화 동시성 제어는 공유합니다.
- Windows exe를 Linux 컨테이너에서 실행하지 않습니다. 원본 폴더를 Linux에 직접 마운트하는 것으로 기존 수집기 경계를 대체하지 않습니다.

## 설치 전에 현장에서 판단할 사항

README의 환경 조사 표를 실제 서버에서 수행합니다. OS/아키텍처, PowerShell/Python, Docker 실행 위치·플러그인, 자원, 포트, 공유 폴더 권한, 복호화 프로그램·서명·인증서·라이선스, 임시 평문 보호/백업 제외, 외부 API와 패키지/모델 다운로드 네트워크를 확인합니다.

현재 기본 실행기는 Windows에서 접근 가능한 WSL Linux Docker를 찾고, Windows Docker CLI의 Linux engine도 확인합니다. 설치기는 Docker daemon이나 다른 운영 서비스를 초기화하지 않습니다. Compose/Buildx 등 환경이 부족하면 AGENT가 조직의 설치 정책에 맞게 준비합니다. 폐쇄망이면 승인된 이미지·모델·wheel을 반입합니다.

복호화 프로그램의 현재 캡처 경로는 `D:/uEncryptor2/uEncryptor2.exe`입니다. 새 서버 설치가 다르면 AGENT가 실제 승인된 설치를 찾아 내부 배포 구성을 맞춰야 합니다. 사용자에게 새 모델/API/로그인 설정 항목을 추가하지 않습니다. `prepare_cpu_server.py`의 `default_config()`가 사용자 폴더 목록에서 기본 구성을 만들며, 필요할 때 AGENT가 검증한 내부 구성을 `--config`로 전달할 수 있습니다. 이는 사용자가 편집하는 공개 설치 설정을 늘리라는 뜻이 아닙니다.

Linux 단독 서버는 현재 전체 구성이 그대로 지원된다고 판단하면 안 됩니다. Windows 수집기가 exe를 실행하고 같은 호스트의 loopback API를 사용하는 제약이 있습니다. Windows 실행 환경 확보 또는 별도 구조 변경·검증이 필요합니다. URL만 바꾼 원격 worker나 Wine 실행을 검증된 대안이라고 주장하지 않습니다.

Windows 작업은 현재 계정 로그인 시 실행됩니다. 로그인 전/로그아웃 후 무인 운영은 WSL/계정/복호화 프로그램의 실제 제약을 현장에서 검증해야 합니다.

## 설정과 비밀값 전달

사용자 입력은 `deployment/source-folders.txt`의 폴더 주소뿐입니다. 한 줄에 한 폴더이며 로컬 절대 경로나 UNC 경로를 사용합니다. 소스 ID는 줄 순서에서 결정하므로 최초 설치 후 기존 항목 순서를 유지합니다. 설치된 소스 구성을 바꿀 때는 기존 문서/소스 식별자와 동기화 상태를 검토하세요. 현재 설치기는 기존 생성 설정을 덮어쓰지 않고 재사용하므로 목록 편집만으로 이미 초기화한 소스가 자동 재설정된다고 안내하면 안 됩니다.

2026-10-19 사용자 요청으로 암호화 설정 파일과 `recovery.key`를 **PRIVATE 저장소의 `deployment/install-inputs`에 함께 포함**하도록 변경했습니다. 이전의 별도 전달 지침은 더 이상 기본 설치 절차가 아닙니다. 최신 `main` 전체를 받으면 설치기가 기존 API/인증 설정을 자동 복원하며, AGENT가 관리자에게 두 파일을 다시 요청하거나 사용자에게 API 키를 입력받지 않습니다. 파일이 없다면 오래된 릴리스/불완전한 복제본인지 먼저 확인합니다.

이 두 파일만 Git/제품 패키지에 포함하도록 명시적으로 승인되었습니다. 그 외 평문 키·생성 설정·원문을 추가하는 일반 허용이 아닙니다. 저장소와 패키지는 비공개로 유지하고 복호화 키/비밀값을 출력하지 않습니다. 암호문과 복호화 키가 함께 있으므로 이 저장소 읽기 권한은 기존 운영 API/인증 설정에 대한 접근 권한도 의미합니다.

생성되는 `.local/cpu-server`에는 `compose.json`, `bootstrap.json`, `gte.json`, worker 설정과 API/인증 키가 있습니다. 비밀 설정은 기존 값을 사용하고 새 DB·색인·객체 볼륨은 비어 있는 상태로 시작합니다. 설치 폴더 이동 시 생성된 절대 경로를 함께 검토합니다.

## 공용 자동 접속 구현을 오해하지 않기

`app/web/src/routes.tsx`는 `/`와 예전 로그인 경로를 DOCMIND 화면으로 보내고, DOCMIND loader는 `initializeDocMindSharedWorkspace()`를 호출합니다. 이 함수가 `/api/v1/docmind/shared-session`을 호출하면 서버가 내부 계정으로 세션 쿠키를 설정합니다. 사용자 비밀번호를 받는 절차가 아닙니다.

내부 이메일 식별자는 DB에서 공용 문서/작업공간의 소유자를 찾는 데 필요합니다. 사용자 로그인 이메일이 아닙니다. 새 설치의 bootstrap은 내부 계정 유형을 유지합니다. 앞선 CPU 초기화 도구가 만든 비밀번호 로그인 계정은 동일한 bootstrap 모델 바인딩으로 자기 작업공간임을 확인한 경우에만 내부 계정으로 되돌립니다. 다른 사용자의 DB를 임의로 인수하지 않습니다.

사용자가 제공했던 VDI REST API 가이드에는 `login.do`/`folders.do`, API 키/토큰, 허용 폴더 경로가 설명되어 있습니다. **해당 VDI 로그인·권한별 루트 자동 등록은 아직 구현하지 않았습니다.** 공용 자동 세션이 VDI 사용자별 인증/ACL을 구현했다는 뜻이 아닙니다. 이번 설치와 별도 연동 과제입니다.

## 검증 근거와 아직 증명하지 않은 부분

CPU 서비스 단위 21개와 OCR 비활성화 회귀 219개를 검증했습니다. 실제 CPU 전용 Linux 이미지도 빌드했고 네트워크 차단·읽기 전용 모델 캐시 상태에서 HTTP 임베딩, CUDA 사용 불가, 한글/영문 768차원 정규화 벡터, 인증 누락 401을 확인했습니다.

이번 공용 세션/단일 경로 설치 변경은 실제 SQLite 모델 초기화와 세션 쿠키 발급 등을 포함한 11개, 폴더 목록/설정 생성 9개를 통과했습니다. 실제 암호화 운영 설정으로 테스트용 빈 폴더의 설정을 생성하고 Compose 구문을 확인했습니다. 원본/worker는 실행하지 않았습니다. 제품 ZIP의 파일 해시, Docker COPY 입력과 Windows 보조 파일 의존성도 검사했습니다. 현재 패키지는 승인된 두 비밀 입력 파일을 포함하며, 그 밖의 소스에는 복호화한 운영 비밀값을 추가하지 않습니다. README Mermaid 그림은 문법 검증했습니다.

프런트엔드는 별도 깨끗한 의존성 설치 후 Vite production build를 통과했지만 전체 TypeScript 검사에는 기존 오류가 남아 있습니다. 모든 타입 검사가 통과했다고 보고하지 않습니다.

이 검증은 **대상 서버에서 모든 이미지를 신규 빌드하고 실제 암호화 문서를 인덱싱하는 전체 인수 시험은 아닙니다.** 새 Windows 계정의 복호화/공유폴더 권한, 실제 네트워크, 자원과 무인 실행 조건은 현지에서 확인해야 합니다. CPU 컨테이너만 성공했다고 전체 설치 완료라고 결론 내리지 않습니다.

## 현지 AGENT의 완료 기준과 보고

1. 대상 환경과 부족했던 의존성, 선택한 Docker 엔진을 기록합니다. 다른 운영 서비스를 변경하지 않습니다.
2. 사용자 입력이 문서 루트 목록뿐인지, 기존 API/모델과 공용 자동 접속을 유지하는지 확인합니다.
3. 신규 볼륨/작업공간이며 기존 문서·벡터 DB를 가져오지 않았는지 확인합니다. 운영 볼륨을 초기화/삭제해서 새 설치처럼 만들지 않습니다.
4. CPU GTE health의 `cpu`·768차원, OCR 비활성화, 웹의 비밀번호 없는 자동 접속을 확인합니다.
5. 허용된 작은 텍스트 문서로 감시→복호화→파싱→색인→검색/근거 답변→원문 미리보기와 양쪽 임시 정리를 확인합니다.
6. 작업 스케줄러·Docker 재기동 조건과 실제 사용자 접속 주소를 기록합니다. 로그인 전 무인 동작을 확인하지 못했다면 구분해 보고합니다.
7. 성공한 검증과 미완료 항목을 구분하고, 로그/보고서에 키·원문·벡터 값을 남기지 않습니다.

운영 서비스 중지·원본 삭제·운영 DB/벡터 이식·공개 저장소 업로드는 이 인수인계만으로 허용되지 않습니다. 대상 서버 배포 범위 안에서 필요한 설치/환경 준비를 수행하고 기존 운영 자산을 보호합니다.
