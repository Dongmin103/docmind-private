# 문서 병렬 인덱싱 구현·측정 결과

2026-10-13. 구현 브랜치 `feat/indexing-concurrency`, 시작점 `8c9e8ed`. 후보 코드의 검증 결과이며 서비스 상시 병렬화 승인이 아니다. 사용자 요청으로 격리한 전체 파이프라인 시험을 수행했고, 시험 중 중지한 기존 수집 워커와 감시기는 복구했다. 상시 서버/워커 실행 설정에는 슬롯 2를 적용하지 않았다.

## 구현

- Windows 감독 프로세스가 최대 두 ingest 워커를 소유한다. worker ID·임시 작업·정리 receipt 경로는 슬롯마다 분리한다. 부모 종료 시 자식 트리 종료, stop 파일에 따른 진행 작업 drain, 자식 재시작 지연을 제공한다.
- 단일 API 프로세스의 문서 admission 상한과 OCR 단독 실행을 추가했다. host cleanup 미완료 작업은 슬롯을 계속 점유한다. claim 응답 유실 후 lease가 만료된 DECRYPTING 작업은 자기 슬롯을 이중 계산하지 않고 새 fencing token으로 재배정한다. 미정리 입력이 있으면 재배정하지 않는다.
- 서로 다른 스레드/이벤트 루프의 cloud-ingestion 임베딩 요청은 한 limiter를 공유한다. 기본 합계 2이며 취소 대기자는 permit을 남기지 않는다.
- artifact의 완료 ACK, 세대·fencing·원자적 활성화, 기존 청킹/모델/차원은 유지한다. 실제 복호화 gate는 1이다.
- Kordoc의 단일 작업 제약을 반영해 API 프로세스의 서비스 URL별 공통 파싱 슬롯을 추가했다. 파서 요청은 기다리되 A 임베딩과 B 파싱은 겹칠 수 있다. 슬롯 대기 시간은 요청 제한 시간에 포함한다.

## 자동 검증과 독립 리뷰

- ingestion service/runtime/limiter: **110 통과**. 실제 네 스레드의 claim 경쟁, OCR 배제, host cleanup 슬롯 유지, 만료 claim 재배정, 두 이벤트 루프의 임베딩 상한/취소 포함.
- 기존 embedding model/service/throughput/settings: **87 통과**. 동기 HTTP 호출 drain, 반복 취소, batch 실패, 결과 순서·벡터 정합성 포함.
- ephemeral input: **14 통과**. 사용 중 workspace 보호와 실패/timeout 정리 포함.
- 실제 claim handler 본문을 실행하는 격리 테스트·측정 집계: **9 통과**. 앱 전체 bootstrap/API 통합 테스트를 대체하지 않는다.
- PowerShell: pool, worker throughput, preview isolation, decrypt gate, preview deployment, host worker, decrypt probe의 7개 self-test 통과. 새 pool 테스트는 실제 자식 중첩/부모 사망, 슬롯별 reaper/receipt 격리와 ACK 유실 시 receipt 유지 확인을 포함한다.

독립 리뷰의 Important 1건(만료 claim의 자기 슬롯 중복 계산)을 4개 실패 테스트로 재현한 뒤 수정했고 위 110개 재실행이 통과했다. Critical/보류 Minor는 없었다. 제품 전체 테스트가 아니라 변경 경로의 좁은 회귀 검증이다.

## 적용 전 남은 검증과 실행 판단

위 비OCR 14개 표본의 전체 파싱→임베딩→ES 가시성→정리 A/B는 완료했다. 실제 SQL/ES에서 구세대/신세대 완료 역전, 처리 중 수정·삭제, lease 만료 경계, 실제 두 슬롯의 artifact ACK 유실·재시작은 별도 검증해야 한다. 최악 크기 입력 두 개의 RAM/임시 디스크, OCR/검색 혼합 부하와 검색 p95도 미측정이다. 처리량 시험의 통과를 이 장애·혼합 부하 검증의 통과로 표현하지 않는다.

구현 기본값은 슬롯 1이며, 상시 슬롯 2 채택은 보류한다. 통제된 시험 적용·복구 방법은 [runbook](DOCUMENT-INDEXING-CONCURRENCY-RUNBOOK.md)에 있다. 복호화 2는 대표 known-pair와 전체 처리 시간의 추가 이득이 입증된 경우에만 별도 구현한다.

진행 중 판단 기록:

1. 앱 기본 디렉터리가 Git 저장소가 아니어서 native worktree 생성이 실패했다. 공유 저장소의 무시되는 `.local/worktrees` 아래 Git worktree로 격리했다. 잘못된 경로 판단 시 작업 분리가 깨질 위험이 있어 git root/branch를 확인했다.
2. WSL bookkeeping이 Windows worktree의 `.git` 경로를 읽지 못해 같은 ledger를 네이티브 파일 도구로 유지했다. 비용은 자동 ledger 검증 일부가 수동 확인으로 바뀐 것이다.
3. 로컬 앱 의존성이 부족해 격리 Docker의 합성 설정과 좁은 pytest 경로를 사용했다. 실제 앱 전체 초기화·외부 SQL/ES 통합을 통과했다는 주장은 하지 않는다.
4. 초기 구현에서는 임베딩 읽기 전용 시험까지만 수행했다. 이후 사용자의 전체 부하 시험 요청으로 별도 DB/ES에서 위 6회 전체 재인덱싱을 수행했다. 공유 API/파서/GTE를 재시작하지 않았으며 수집·감시 작업만 시험 동안 중지 후 복구했다.
5. 리뷰가 범위 밖으로 둔 다중 API 프로세스 admission은 지원하지 않는다. 이 제한을 무시한 배포에서는 상한이 보장되지 않는다.
6. 이 비OCR 표본의 전체 처리량 개선은 확인했다. 전체 형식/크기 분포의 일반화, OCR/검색 혼합 부하와 복호화 동시성 2의 호환성은 미확정이며 상시 배포 합격 판정은 보류한다.
7. standalone/pool 전환은 모든 기존 workspace·receipt를 원래 identity로 drain한 뒤 수행한다. 자동 잔여 작업 이관은 제공하지 않으며 이를 어기면 복구가 지연되거나 다른 실행 주체가 정리를 시도할 위험이 있다.
