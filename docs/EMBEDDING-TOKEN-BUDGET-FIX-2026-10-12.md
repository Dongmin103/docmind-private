# Cloudflare BGE-M3 요청 토큰 한도 수정

2026-10-12. 대상: OCR 미사용 전체 측정에서 발생한 HWP 7개·PPTX 1개의 임베딩 오류.

## 원인과 변경

기존 OpenAI 호환 어댑터는 배치 32개를 적용했으나 `EMBEDDING_REQUEST_TOKEN_LIMIT=0`일 때 Cloudflare 요청의 전체 토큰 수를 제한하지 않았다. 실제 공급자는 61,440~122,148토큰 요청을 최대 60,000토큰 초과로 거부했다. [공식 모델 문서](https://developers.cloudflare.com/workers-ai/models/bge-m3/)도 60,000토큰 문맥 한도를 명시한다.

- `api.cloudflare.com` 및 `gateway.ai.cloudflare.com`의 `@cf/baai/bge-m3`에 요청 합계 기본 상한 60,000을 적용한다. 명시 설정은 더 작은 값만 유효하며 큰 값으로 공급자 상한을 해제하지 못한다.
- 기존 로컬 cl100k 토큰 계산으로 전송 전 배치를 나눈다. 로컬 계산과 공급자 계산이 같다고 보장하지 않는다.
- 해당 공급자·모델의 HTTP 400 `Max context reached ... model supports only ...` 오류에 한해 배치를 절반씩 나눠 순차 재요청한다. 매번 입력 개수가 줄어들며, 단일 입력까지 실패하면 오류를 반환한다. 새로운 잘라내기로 입력 내용을 버리지 않는다.
- 기존 배치 최대32·동시성2 설정, 청킹, 입력별 절단 계약, 벡터 정렬·검증·제목 혼합을 유지한다. 분할은 기존 limiter 안에서 실행하며 새 병렬 요청을 만들지 않는다.
- 성공한 하위 요청의 사용량만 합산한다. 일부 하위 요청이 실패하면 전체 encode가 실패하고 문서에 부분 벡터를 붙이지 않는다.
- 다른 모델·호스트, 일반 HTTP 오류는 분할 재시도하지 않는다.

## 검증

격리된 `docmind-ragflow-pytest:kordoc-pilot`에서 소스를 읽기 전용으로 연결하고 네트워크 없이 실행했다.

1. 수정 전 신규15개 테스트: 6실패·9통과. 기본 상한 누락, 큰 설정으로 상한 초과, 공급자 토큰 계산 차이 시 복구 실패를 재현했다.
2. 수정 후 신규15개와 기존85개 회귀: 100통과, 12.12초.
3. 서비스 통합 테스트2개 추가 후 관련41개: 41통과, 9.79초. 성공 시 순서·사용량·차원, 실패 시 부분 벡터 미부착, 최대동시성2와 limiter 반환을 검증했다. 고유 검증 범위는 총102개다.
4. `python app/scripts/verify_removed_runtime.py` 통과. `git diff --check` 통과.
5. Ruff는 Windows Python과 시험 이미지에 설치되어 있지 않아 실행하지 못했다.

실제 Cloudflare 합성 입력 검증 도구를 준비하고 운영 컨테이너의 별도 Python 프로세스에서 실행했다. 본문·키는 출력하지 않고 DB는 조회만 허용했다. 사전 점검에서 `leased_ingestion_jobs=59`를 확인하여 API 호출 전에 종료했다. 실제 API 요청0개·원본 문서 사용0·DB 변경0이다. 수정 모듈은 별도 프로세스에만 로드했으며 운영 프로세스에는 배포하지 않았다.
