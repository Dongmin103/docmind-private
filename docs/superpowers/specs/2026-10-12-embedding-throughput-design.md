# 임베딩 처리량 개선 (우선순위 5–7)

## 목표와 범위
서비스와 OpenAI 호환 어댑터에 중복된 16개 제한을 조정 가능하게 만들고, 제목을 첫 본문 배치와 함께 요청하며, 제한된 배치 동시 실행을 지원한다. 전체 인덱싱의 5–7번 후속 작업이다. 운영 배포와 실제 문서 재인덱싱은 포함하지 않는다.

## 보존할 계약
- BGE-M3, 청킹, C128, prefix2400, Jina reranker v3.5는 변경하지 않는다.
- 기존 제목 하나를 모든 청크에 같은 가중치로 혼합하는 수학적 결과, 본문/제목의 기존 전처리와 truncation, 벡터 순서와 토큰 합계를 보존한다.
- 잘못된 응답/일부 배치 실패에서 부분 벡터를 문서에 붙이거나 성공으로 기록하지 않는다.
- 공유 embed limiter를 준수한다. 동시 실행 중 실패/취소 후 남은 요청이 무제한 실행되거나 limiter를 조기에 반환하지 않도록 검증한다.
- 다른 공급자 및 하위 클래스의 기존 제한은 명시적 지원 근거 없이 올리지 않는다. 공급자 범용 설정과 특정 API 제한을 구분한다.
- 비밀, 원문, 인증 포함 URL은 계측하지 않는다. 기존 사용량/관측 래퍼를 우회하지 않는다.

## 설계
배치 크기를 명시적으로 설정하여 서비스와 대상 어댑터 모두에 반영한다. 요청 수뿐 아니라 실제 공급자의 총 입력 토큰/항목 제한을 지킨다. 미검증 공급자의 기존 기본값을 유지한다. 초기 비교 후보는 16/32/64개, 동시 호출은 1/2개다. 기본 동시성은 실제 공급자 검증 전에는 1을 유지한다. 런타임 설정 파일은 수정하지 않는다.

제목을 첫 요청 입력의 선두에 넣고 해당 벡터를 분리해 기존 가중 혼합에 사용한다. 제목도 배치 항목 제한에 포함한다. 본문은 기존 방식으로 전처리한다. 한 요청에 합칠 때 전처리가 달라지는 공급자에는 보수적인 경로를 유지한다.

동시성은 제한된 작업자 수로 구현하고, 완료 순서와 입력 순서를 분리한다. 진행률은 완료된 본문 수를 기준으로 단조 증가한다. 모델/LLMBundle의 공유 상태와 DB 사용량 갱신을 확인한 뒤 안전한 경로에만 허용한다. 추가 자동 재시도 계층을 만들지 않는다.

각 배치의 입력 수, 토큰 합계, limiter 대기와 encode 경과 시간을 구분해 측정한다. encode 시간에는 SDK 내부 재시도/네트워크/공급자 계산이 포함될 수 있으며 이를 실제 모델 계산 시간으로 부르지 않는다.

## 검증과 근거
합성 입력과 지연을 통제한 공급자 stub으로 기존/제목통합/배치확대/동시성2를 비교한다. 요청 수, 결과 동일성, 실제 최대 동시 요청 수, 오류 전파, 취소, 총 시간을 기록한다. 합성 성능을 운영 단축률로 보고하지 않는다.

공식 OpenAI API는 요청당 합계 300,000토큰 제한을 설명한다. 기존 코드의 'OpenAI requires batch size <=16' 주석은 공급자 계약 근거가 아니다: https://developers.openai.com/api/reference/resources/embeddings/methods/create
Cloudflare BGE-M3는 별도 공급자 계약이므로 OpenAI 서비스 제한을 그대로 적용하지 않는다: https://developers.cloudflare.com/workers-ai/models/bge-m3/
