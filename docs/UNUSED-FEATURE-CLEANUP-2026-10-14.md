# 불필요한 실행·로딩·미참조 코드 정리

사용자 요청으로 실행 구성, 백엔드 의존성, 프런트 참조 관계를 세 에이전트가 조사했다.
현재 DocMind 검색·답변·인덱싱·미리보기·모델/프로필 설정·선택 OCR은 보존한다.
관리자 API도 필요 시 실행하는 기능을 유지한다.

## 이번 정리 범위

| 대상 | 확인한 근거 | 처리 |
|---|---|---|
| 옛 BGE 자동 시작 | 현재 GTE를 쓰고 BGE 컨테이너는 이미 중지됐지만, Windows `full` 구성과 API 의존성이 BGE를 다시 시작하게 함 | 자동 시작·API 의존성 제거. 명시적 `bge-cpu` 프로필은 복구 절차용으로 유지 |
| 사용하지 않는 검색·저장소 드라이버의 사전 로딩 | `common/settings.py`와 상태 확인 모듈이 선택하지 않은 엔진·저장소 어댑터까지 import | 실제 선택된 엔진/저장소 분기에서만 import. 기존 엔진·암호화·감사 래퍼 계약 유지 |
| 이전 홈 화면 | `/home`은 DocMind로 이동하며 이전 홈 화면의 외부 참조 없음 | 해당 화면 파일 9개 삭제 |
| 플러그인 도구 보조 코드 | hook/service/type 세 파일의 참조가 해당 묶음 안에만 존재 | 세 파일과 전용 API 상수 삭제 |
| 미참조 dataflow API 어댑터 | 실제 결과 화면은 다른 경로를 사용 | 어댑터 파일과 전용 상수 5개 삭제. 실행 중인 dataflow 화면·취소 API는 유지 |
| 미참조 청크 화면 wrapper | DocMind는 하위 `knowledge-chunk`를 직접 사용 | wrapper 파일 하나만 삭제. 청크 확인·임시 원문·좌표 강조 유지 |

프런트 삭제는 총 14개 파일·전용 API 상수 6개다. 이 코드는 이미 진입 그래프에서
제외돼 있었으므로 저장소 유지보수 정리이며, 런타임 RAM 절감으로 계산하지 않는다.
BGE도 이미 꺼져 있어 이번 시작 설정 정리의 즉시 메모리 절감량은 0이다.
드라이버 import 변경의 실제 RAM 절감량은 별도로 측정하지 않았다.

## 유지하거나 별도 판단이 필요한 항목

- **에이전트·장기 메모리·그래프·범용 채팅 등:** DocMind 메뉴에서 보이지 않아도
  라우트와 API가 남아 있다. 전체 기능 삭제 여부를 사용자에게 확인 중이므로 이번에는 유지한다.
- **Artifact/그래프 렌더러:** DocMind가 재사용하는 청크 화면에서도 접근 가능하다.
  그래프 폴더를 통째로 지우면 현재 화면을 깨뜨릴 수 있다.
- **로그인·프로필·모델 설정:** DocMind와 관리자 화면이 공유하는 코드가 있어 유지한다.
- **Infinity/psycopg2/botocore 패키지:** 선택하지 않은 엔진 드라이버와 별개로
  현재 토큰화·DB 모듈·모델 공급자 설정에서 참조한다. 패키지 자체를 삭제하지 않는다.
- **RAPTOR/GraphRAG/Dataflow 공통 코드:** 특수 작업은 DocMind의 일반 수집 경로와 다르지만,
  다른 등록 API가 사용하고 일부 그래프 유틸은 현재 인덱싱에서도 공유한다. 일괄 삭제하지 않는다.
- **Surya OCR·MinIO·미리보기 처리기:** 선택 OCR 요구와 현재 저장소·미리보기 계약을 유지한다.
- **Go/MCP 경로:** 현재 실행 중이지 않아 즉시 메모리 절감 대상이 아니다. 공용 배포 경로는 유지한다.
- **보안 gate:** 정상 종료된 일회성 검사이므로 상시 메모리를 쓰지 않는다. 제거하지 않는다.
- **남은 TEI/BGE 기본 설정:** 현재 GTE 배포 환경에도 `tei-cpu`/BGE 기본값이 남아,
  중지된 BGE를 모델 목록에서 사용 가능하게 표시할 수 있다. 기존 GTE 바인딩과 새 workspace
  기본 모델 계약을 함께 검증해야 하므로 이번 자동 시작 정리와 섞어 바꾸지 않았다.

이미지·모델 캐시·기존 컨테이너·원본·DB·청크·벡터 볼륨은 삭제하지 않았다.
앞선 267.4초 인덱싱 기록은 이 코드 정리 이전 실측이며, 이번 변경의 성능 결과가 아니다.

## 회귀 검증

- 실제 배포 이미지의 의존성을 사용한 네트워크 차단 테스트 컨테이너에서
  새 import 경계 검사·기존 GaussDB 설정/상태·OceanBase 상태·임베딩 병렬 설정
  **74개를 함께 실행해 통과**했다. 기존 Peewee 폐기 예정 옵션 경고 68개는 남아 있다.
- 주요 화면·라우트·공유 세션·OCR 선택·내장 청크 화면 **5개 Jest suite / 48개 검사 통과**.
- 실제 Compose 구성 **8개 조합**, 기존 generationless/preview 설정 **7개 검사 통과**.
- 제거된 runtime 재유입 검사와 `git diff --check` 통과. 독립 검토에서 발견한
  기존 health 테스트 patch 대상 및 가짜 드라이버 모듈의 테스트 간 누출을 수정했다.
- 전체 TypeScript 검사는 기존 오류 때문에 통과하지 않는다. 동일 컴파일러·동일 의존성에
  변경 전 소스를 compiler host로 대입한 통제 비교에서 **1,981건 → 1,978건**, 신규 오류 0건이다.
  타입 표시의 생략된 속성 개수만 정규화했으며, 줄어든 3건은 삭제된 홈 파일의 오류다.
  서로 다른 `node_modules`를 쓰는 주 checkout과의 단순 비교는 판단 근거에서 제외했다.
- 변경한 기존 Python 파일의 Ruff 진단은 변경 전후 동일한 63건이고 신규 진단은 없다.
  새 import 테스트 파일은 Ruff를 통과했다. 기존 전체 lint/type 오류를 이번 정리에서 고치지 않았다.
- 프런트 운영 빌드는 다시 하지 않았다. 삭제된 코드는 기존 진입 그래프 밖에 있으며,
  실행 중인 프런트 자산은 보존한다. 추가 인덱싱 성능 시험도 수행하지 않는다.

## 배포 완료 및 복구 기록

사용자의 WSL 재시작 승인 후 Ubuntu와 DocMind 서비스를 복구하고 배포를 완료했다.
아래 연결 오류는 배포 전 발생한 기록이며, 현재 상태는 다음과 같다.

- API 이미지: `docmind-ragflow:lazy-backends-20261014`
  (`sha256:95ce5f04b2dce00ac6ef9605a9098a30b15f4730bcbeb2cd72e3cd353dd803fd`).
  코드 출처는 `9447a9b`이며 변경한 두 파일의 실행 컨테이너 SHA-256이 일치한다.
- 진행 작업·임시 파일이 없는 것을 확인하고 기존 컨테이너 8개를 정상 종료했다.
  Ubuntu 재시작 후 이미지를 완성하고 API 교체 및 기존 의존 서비스 복구를 마쳤다.
  빌드·기동 후 파일 캐시를 일회성 반환했다. 영구 메모리 설정은 변경하지 않았다.
- API·GPU·파서 준비 상태, 로컬/공개 화면 해시와 API 응답, 미인증 워커 요청의 401을 확인했다.
  합성 GPU 요청 2개에서 벡터 6개가 기존 결과와 코사인 유사도 1.0으로 일치했다.
- 실제 공용 세션·폴더·모델 목록 조회 및 검색을 통과했다. 검색 후보는 BM25 128개,
  dense 128개이며 최종 결과 5개를 반환했다. 검색 시간은 성능 비교로 사용하지 않는다.
- 정상 문서 223개·청크/벡터 12,460개와 원본 244개의 해시·크기·수정 시각을 확인했다.
  OCR 요청 0, 임시 파일 0, 정리 대기 0이며 기존 처리 시도 합계 244회를 유지했다.
- 인덱싱·미리보기·원본 감시·WSL 유지·GPU 작업 5개 모두 Running이다.
  관리자 API와 옛 BGE는 중지 상태를 유지하고, 기존 병렬도·GPU 배치·포트·볼륨·자원 한도는 보존했다.
- 실행 중인 프런트 자산은 보존했다. 추가 전체 색인 시험과 RAM 절감량 비교는 하지 않았다.

### 배포 전 장애 기록

- 코드 커밋 `9447a9b`를 개발 배포 브랜치에 병합했다.
- 새 API 이미지 `docmind-ragflow:lazy-backends-20261014` 빌드 중 WSL 명령 연결이
  `Wsl/Service/0x8007274c`로 반복 실패했다. 첫 빌드 호출은 240초 제한을 초과했고,
  재시도도 두 번째 파일 COPY 단계에서 진행되지 않아 중단했다. 새 이미지 완성은 확인되지 않았다.
- 당시 API 컨테이너 교체와 워커 일시 중지는 수행하지 않은 상태였다. 실행 API는
  기존 `docmind-ragflow:cloud-cleanup-lease-20261014`였으며 새 코드 적용 전 발생했다.
- 문제 발생 시 Windows 가용 메모리 616MiB, 커밋 사용률 92%, 페이지 읽기 3,435회/초가
  관찰됐다. WSL에서는 캐시 약 7GB와 스왑 사용 약 2GB가 관찰됐다. 메모리 압박은 확인되지만
  정확한 WSL 내부 대기 원인은 확정하지 않았다.
- 기존 API·화면은 HTTP 200이었고 GPU 상태 요청은 시간 초과했다. 캐시 반환 시도도
  WSL 연결 오류로 끝나 실행 성공을 확인하지 못했다. 공유 서비스 중단을 수반하는
  WSL 재시작은 사용자 확인 후 진행해 위와 같이 복구·검증을 마쳤다.
