# 인덱싱 개선 실서비스 검증 — 2026-10-12

## 실제 공급자 API 비교

현재 바인딩된 Cloudflare BGE-M3에 생성한 비민감 텍스트를 보냈다. 실제 EmbeddingService → LLMBundle → OpenAI_APIEmbed 경로를 사용했으며, 배포 전 별도 프로세스에 새 소스를 로드했다. 이 비교 자체는 실행 중인 앱 소스나 기존 문서 데이터를 변경하지 않았다.

96개 본문과 제목 하나를 동일하게 사용하고 여섯 구성을 교차 순서로 3회씩 측정했다. 사전 확인을 포함한 실제 API 요청 82회가 모두 HTTP 200이었다.

| 구성 | 회당 요청 수 | 관측 최대 동시 요청 | 중앙값(초) |
| --- | ---: | ---: | ---: |
| 기존 제목 별도 + 본문 16개 직렬 | 7 | 1 | 3.586305 |
| 제목 통합, 16개 직렬 | 7 | 1 | 4.966923 |
| 제목 통합, 32개 직렬 | 4 | 1 | 3.456200 |
| 제목 통합, 64개 직렬 | 2 | 1 | 2.250448 |
| 제목 통합, 32개·동시성 2·공유 용량 2 | 4 | 2 | 1.810162 |
| 제목 통합, 64개·동시성 2·공유 용량 2 | 2 | 2 | 1.736217 |

배포 설정은 `EMBEDDING_BATCH_SIZE=32`, `EMBEDDING_BATCH_CONCURRENCY=2`, `MAX_CONCURRENT_EMBEDDING_REQUESTS=2`로 선택했다. 이 표본의 임베딩 중앙값은 기존보다 49.53% 짧았다. 64개·동시성 2는 선택한 구성보다 약 4.1% 빨랐지만 요청당 최대 입력 수가 두 배여서 첫 배포에는 32개를 선택했다. 동시 호출이 불가능한 경우 이번 표본에서는 64개 직렬이 기존보다 37.25% 짧았다.

모든 결과는 1,024차원의 유한 벡터이며 입력 순서와 개수가 맞았다. 배치 크기에 따라 결과가 비트 단위로 동일하지는 않았다. 기준 대비 최소 코사인 유사도는 0.9999805543, 최대 좌표 절댓값 차이는 0.0007236481이었다. 생성 입력별 가장 가까운 기준 벡터의 순서는 일치했다. 실제 문서의 검색 품질 검증을 대신하지 않는다.

입력은 로컬 tokenizer 추정으로 총 622,166토큰이었다. 모든 응답에서 공급자 사용량이 제공되지 않았으므로 반환 사용량 0을 무료 호출이나 실제 과금량으로 해석하지 않는다. Langfuse는 비활성이었다. 이 결과는 생성 텍스트의 실제 공급자 호출 시간이며, 전체 문서 등록·복호화·파싱·색인 시간을 49.53% 줄였다는 뜻이 아니다.

## 배포 준비와 현재 상태

소스 기준은 `24619e4`다. 기존 실행 이미지 위에 임베딩 관련 백엔드 파일 4개만 덮어쓴 이미지 `docmind-ragflow:indexing-throughput-20261012-r1`을 생성했다. 이미지 ID는 `sha256:a28bd5b81eff8d56e287488e9199aec21493b844ada634b0428c64912de22074`다. 호스트 감시기·워커 관련 파일 4개와 기존 실행 설정의 복구본도 로컬에 준비했다.
