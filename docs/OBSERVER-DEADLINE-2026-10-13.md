# 문서 처리 완료 확인 지연 조사

기존 20.60초 문서 처리 결과는 유지된다. 이번 작업은 문서 처리 후 시험 제어기가 완료를 확인하기까지의 19.81초를 조사하고, 제어기 조회의 무제한에 가까운 대기를 제한했다. 문서·GPU 벤치마크를 추가로 실행하지 않았다.

## 기존 기록으로 확인한 범위

- 호스트의 마지막 정리·ACK까지 20.599초, 제어기의 실행 시작→완료 관측은 41.874초였다. 시작 전 준비 1.469초와 완료 후 관측 지연 19.806초가 별도로 포함된다.
- API의 짧은 제어 작업은 성공했고, GPU 표본 수집과 약 3.5초 간격의 자원 조회도 계속됐다. 완료 후 대응하는 API 이벤트 루프 차단은 기록되지 않았다.
- 상태 관측 쪽에 약 33초 공백이 있었지만, 당시 제어기는 연결·응답 읽기·재시도 오류를 기록하지 않았다. 따라서 네트워크 연결, 응답 전달 또는 제어기 내부 중 정확히 어느 구간인지 과거 로그만으로 확정할 수 없다.
- 제어기는 상태 요청에 소켓 timeout 90초를 사용하고 최대 6회 재시도했다. 이 동기 요청이 진행되는 동안 완료 확인 루프도 멈추는 구조였다. `__bench_control`은 시험 환경에만 추가한 경로다. 실제 제품 화면에 동일 지연이 발생했다는 증거는 없다.

## 수정

`tools/local_embedding/benchmark_control.py`의 `ControlClient`를 기존 비공개 시험 제어기 `.local/gpu-feed-20261013/run.py`에 연결했다. 상태·자원·오류·검증 조회는 요청 전체 2초 제한을 사용한다. 연결, 요청 전송, 응답 헤더, 본문 단계와 HTTP 상태·예외 종류·경과 시간을 기록한다. 인증 토큰, 응답 내용과 예외 메시지는 기록하지 않는다.

시간 초과 시 소켓을 종료해 헤더나 본문이 조금씩 도착하는 경우에도 제한을 적용한다. 요청 내부의 숨은 재시도는 없으며, 상태 조회 실패 시 완료로 간주하지 않고 0.2초 후 다음 조회를 시도한다. 전체 시험의 기존 600초 제한과 최종 성공·정리 검증은 유지한다. `reset` 등 변경 요청은 이 클라이언트에서 허용하지 않으며 기존 경로를 유지했다.

새 파일로 시험 제어기를 구성할 때는 위 helper를 import하고 `ControlClient(19390, token, timeout=2, record=record_control).call(action)`으로 읽기 전용 요청을 보낸다. 기록 콜백은 동시 호출에 안전하게 JSONL을 저장해야 한다. `OSError`는 바깥 상태 확인 루프에서 기록된 실패로 처리하고 다시 조회하되, 실패를 성공 응답으로 바꾸지 않는다.

## 검증과 한계

운영 서비스는 중지하지 않고 같은 Windows→Docker 포트 경로에 별도 합성 응답 서버를 띄웠다.

| 검증 | 결과 |
| --- | --- |
| 기존 urllib 경로, 상태·자원 동시 조회 200회 | 오류 0, 최대 0.074초; 과거 긴 지연 미재현 |
| 수정 클라이언트 동시 조회 100회 | 오류 0, 최대 0.037초 |
| 지연·오류 주입 회귀 테스트 | 5개 통과 |

회귀 테스트는 멈춘 응답 헤더, 천천히 전송되는 본문, HTTP500, 오류 후 다음 조회 성공, 민감값 미기록, 변경 요청 거부를 확인했다. 단축된 0.12초 제한으로 전체 제한을 시험했다. 독립 읽기 전용 리뷰에서도 중요한 결함이 발견되지 않았다.

2초 제한은 네트워크 요청에 적용된다. 기록 콜백 자체의 파일 I/O 시간은 별도이며, 클라이언트의 시간 초과가 서버 DB 작업을 취소하지는 않는다. 지속적인 서버 지연에서 재조회 부하까지 검증한 시험은 아니다.

이 결과는 느린 조회 하나가 제어기를 수십 초 묶는 구조를 개선했다는 근거다. **과거 지연의 정확한 원인이 밝혀졌거나, 실제 문서 시험의 완료 확인 시간이 단축됐음을 새로 실측했다는 뜻은 아니다.** 기존 20.60초 기록을 새 측정값으로 대체하지 않는다.

합성 서버 컨테이너를 제거하고 원래 GPU/API HTTP 200을 확인했다. 상세 수치는 [측정 JSON](measurements/observer-deadline-2026-10-13.json)에 기록했다.
